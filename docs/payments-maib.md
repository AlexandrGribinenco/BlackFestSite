# Оплата картой через maib — план

Документация maib: https://docs.maibmerchants.md/e-commerce (API), https://docs.maibmerchants.md/main/ro/integration/requirements (требования к сайту).

## Как работает maib e-commerce (Direct payment)

1. Покупатель жмёт «Pay» в Checkout. **Наш сервер** получает токен (`/v1/generate-token`, Project ID + Project Secret), сам считает сумму заказа и создаёт платёж (`/v1/pay`).
2. maib отвечает ссылкой `payUrl`. Покупатель уходит на страницу maib и вводит там карту или платит через Apple Pay / Google Pay. Проходит 3-D Secure.
3. maib отправляет итог **на наш сервер** (`callbackUrl`, POST с подписью SHA-256 по Signature Key) и возвращает покупателя на `okUrl` / `failUrl` с `payId` и `orderId`.
4. Сервер проверяет подпись, отправляет письмо-подтверждение. Страница возврата показывает номер заказа, состав и дату.

Карта на нашем сайте не вводится. Поля карты из макета D3 / M4.4 убраны, на шаге Payment теперь объяснение и переход на maib.

## Главное: чего не хватает

### 1. Сервер — на GitHub Pages оплату не подключить
GitHub Pages отдаёт только статические файлы. Негде хранить Project Secret и Signature Key, некуда принимать callback от maib. Нужен хостинг с серверным кодом. Кроме того, при регистрации в Merchant Portal maib просит **IP-адрес сервера**, то есть нужен постоянный IP.

**Решение: хостинг клиента в host.md, Node.js в Plesk** (рекомендация — Premium Hosting). Что host.md подтвердил:
- Node.js новее 20.9 на любом пакете;
- модуль Git в Plesk;
- постоянный IP.

SSH на Shared нет, но он не нужен: сайт собирается в GitHub Actions и приходит в Plesk через Git. Настройка — [deploy-hostmd.md](deploy-hostmd.md).

**Ждём ответа host.md:**
- разрешены ли исходящие HTTPS-запросы к `api.maibmerchants.md`;
- есть ли SSH на Premium.

Если исходящие запросы закрыты — запасной вариант VPS.

### 2. Домен
Для продакшена maib проверяет сайт и записывает его домен в Merchant Portal; адрес `*.github.io` для этого не подходит. Нужен свой домен с HTTPS.

У клиента в host.md есть `auroraaustralishub.com.md`, оплачен до 30.09.2027. Сейчас он не открывается: DNS отвечает ошибкой, прежний хостинг удалён. Тот же адрес указан в заявке maib, поэтому сайт фестиваля лучше открыть на нём.

### 3. Заявка и договор с maib — проверить у банка
- В заявке ECOMM от 09.10.2025 интернет-магазином указан **www.auroraaustralishub.com.md**, а деятельность — «визуальные проекты, картины, мерчандайзинг». Ни сайта фестиваля, ни продажи билетов там нет.
- По универсальному договору (п. 12.4.3) банк может закрыть счета, если операции не соответствуют заявленной деятельности.
- **Клиенту нужно уточнить у maib** (ecom@maib.md или менеджер, принимавший заявку):
  - можно ли принимать оплату на сайте фестиваля по этой заявке или нужна новая или изменённая заявка: новый сайт и деятельность «продажа билетов на мероприятия»;
  - можно ли подключить тестовый доступ на тестовый адрес до появления домена.

### 4. Тест и «реальный платёж 25 $»
- Тестовый доступ: письмо на **ecom@maib.md** с адресом сайта и типом интеграции (Direct payment по API). В ответ приходят тестовые Project ID, Project Secret, Signature Key.
- В тесте платят **тестовой картой** из документации (Test Test, 5102 1800 6010 1124, 06/28, CVV 760). Деньги не списываются: проверить реальной картой в тесте нельзя.
- Реальный платёж возможен только после запуска: maib проверяет сайт, подписывается договор эквайринга, сайт регистрируется в Merchant Portal (домен, платформа, IP сервера), активируется Production Project. Первую транзакцию maib сам просит сделать на **10 MDL**.
- Валюта: maib принимает MDL, EUR, USD. На сайте сейчас MDL (`CURRENCY` в `src/lib/checkout.ts`). Платёж в долларах возможен, только если это позволяет договор. Решить с клиентом.

### 5. Цены
Все цены на сайте — заглушки `[PRICE]`. Сервер считает сумму сам, по каталогу, и без цен платёж не создаст. Нужны цены хотя бы для одной категории билетов (поле `amount` в `TICKET_TYPES` / `ADDONS`, файл `src/lib/checkout.ts`).

### 6. Почта
Письмо-подтверждение обязательно. Код готов: `src/server/email.ts`, SMTP через nodemailer. Письмо оформлено по макету D9, к нему приложен PDF с электронными билетами.

host.md запрещает отправку через сторонние SMTP и сервисы, поэтому письма уходят с ящика на домене сайта, через почтовый сервер хостинга. Ограничения:
- 500 писем в час на домен;
- 20 получателей в письме.

Ящик, DKIM и SPF настраиваются в Plesk ([deploy-hostmd.md](deploy-hostmd.md)).

## Что уже сделано в коде

- `src/server/maib.ts` — клиент API: токен с обновлением, `/pay`, `/pay-info`, `/refund`, проверка подписи callback.
- `src/server/orders.ts` — сервер проверяет заказ и считает сумму по каталогу, создаёт номер заказа.
- `src/server/email.ts` — письмо-подтверждение по макету D9 с обязательными полями maib, отправка через SMTP хостинга.
- Электронные билеты в PDF по макету D9 (`src/lib/ticket-pdf.ts`): A4, страница на каждый билет — на каждое место для билетов с местом — и на каждый доп (парковка, кемпинг).
  - Сервер прикладывает PDF к письму после оплаты (`src/server/tickets.ts`).
  - В Checkout кнопка «Download PDF» собирает тот же PDF в браузере.
  - Билеты с местами уходят в maib отдельной позицией на каждое место, чтобы из оплаченного заказа получались билеты без базы данных.
- `src/app/api/payments/…/route.api.ts`:
  - `POST /api/payments` — создать платёж;
  - `POST /api/payments/callback` — итог от maib;
  - `GET /api/payments/:payId` — статус для страницы возврата.
  
  Эти маршруты собираются только на сервере; статическая сборка для GitHub Pages их пропускает (`pageExtensions` в `next.config.ts`).
- Checkout: шаг Payment без полей карты, переход на maib, ошибки; страница `/checkout/result`. Пока `NEXT_PUBLIC_PAYMENTS_API_URL` не задан, оплата имитируется как раньше, поэтому тестовый сайт не меняется.
- T&C по шаблону maib, данные компании, `.env.example` со всеми настройками.
- Сборка для хостинга: workflow Build for hosting (`.github/workflows/hosting.yml`) собирает сайт в режиме `standalone` и кладёт его в ветку `deploy` для Plesk Git. Инструкция — [deploy-hostmd.md](deploy-hostmd.md).

**Ничего из этого ещё не запускалось и не тестировалось**: ни запросов к maib, ни тестовых оплат. Тестируем вместе, когда будут ключи и сервер.

## Порядок работ

1. **Решения клиента**:
   - купить хостинг в host.md (рекомендация — Premium Hosting) и вернуть домен в работу;
   - валюта;
   - цены для теста;
   - телефон и e-mail для покупателей;
   - правила возврата билетов и доставки мерча (для T&C);
   - согласовать с maib сайт и вид деятельности (пункт 3).
2. **Тестовый доступ**: письмо на ecom@maib.md. Параллельно — анкета maib (её заполняет клиент).
3. **Инфраструктура** — по [deploy-hostmd.md](deploy-hostmd.md):
   - HTTPS, почтовый ящик, Git и Node.js в Plesk;
   - тестовые ключи maib в переменных окружения Plesk;
   - входящие запросы от maib (91.250.245.70, 91.250.245.71, 91.250.245.142) должны доходить до сайта.
4. **Тест вместе**: оплата тестовой картой, отказ, таймаут, повтор. Проверить письмо и страницу возврата. Отправить `payId` успешного платежа на ecom@maib.md.
5. **Доработки до продакшена**:
   - база данных заказов: защита от повторных писем, учёт оплат;
   - подпись кода в QR и проверка билетов на входе (сканер). Сейчас QR содержит номер заказа и номер билета;
   - удержание мест на сервере;
   - сохранение корзины после неудачной оплаты;
   - официальные логотипы;
   - описания товаров;
   - возвраты в админке;
   - фискальный чек — уточнить у бухгалтера.
6. **Продакшен**:
   - проверка сайта банком;
   - договор эквайринга;
   - Merchant Portal: домен, платформа, IP сервера;
   - Production Project: Callback / Ok / Fail URL;
   - продакшен-ключи в `.env`;
   - платёж на 10 MDL, затем реальный платёж клиента.
7. **Shop**: корзина и оформление заказа мерча (D12) готовы, оплата в них пока имитируется. Осталась серверная часть:
   - расчёт корзины и доставки на сервере;
   - сохранение заказа с адресом для курьера (у maib адреса нет) и письмо организатору;
   - платёж maib, как для билетов.
